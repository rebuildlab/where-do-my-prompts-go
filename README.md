# Where Do My Prompts Go?

A sourced tracker of how AI tools handle your data: training defaults, retention,
zero data retention, abuse-monitoring exceptions, regions (Singapore/APAC called out),
SOC 2 / ISO 27001, HIPAA BAAs and self-host options.

Every field in `data/vendors.json` has `value`, `detail`, `quote`, `source` and `checked`.
If an official page didn't clearly say it, the value is `unverified`.

## Layout

```
data/vendors.json            source of truth (one record per tool)
data/changelog.json          confirmed policy changes shown on /changelog/
scripts/build.py             static site generator -> public/ (HTML, inline SVG charts, llms.txt; stdlib only)
scripts/derive.py            status colours, retention parsing and headline stats shared by the build
scripts/make_graphics.py     og.png, og/<slug>.png, favicon.ico, apple-touch-icon.png (needs Pillow)
scripts/fonts/               IBM Plex Mono TTFs for the PNG cards (SIL OFL 1.1)
scripts/export_hf.py         flat CSV/JSONL + dataset card -> hf-dataset/
scripts/check_policies.py    nightly fetch + snapshot + diff -> changes/YYYY-MM-DD.md
scripts/checker_config.json  noise filters and extra URLs for the checker
site/assets/                 style.css, app.js, fonts/ (Plex Mono woff2 subset), copied into public/assets
snapshots/                   main-text snapshot per source URL + index.json
changes/                     diff reports, one file per day with changes
public/                      built site (generated; safe to delete)
hf-dataset/                  Hugging Face dataset export (generated by export_hf.py)
.github/workflows/check-policies.yml   nightly run of the checker
```

## Build and preview

```
pip install pillow          # optional locally; needed for og.png / favicon PNGs
python3 scripts/build.py
python3 -m http.server 8080 --directory public   # keeps working across rebuilds
```

Every number, colour and chart on the site is computed from `data/vendors.json` at build
time. Colour rules live in `scripts/derive.py` and are printed on the Method page.
`python3 scripts/derive.py` prints the status of every field and the headline stats so you
can check them by eye. Without Pillow the build still works but skips the PNG social cards
(set `REQUIRE_GRAPHICS=1` in CI so a missing Pillow fails the deploy instead).

For production, set `SITE_URL` (adds canonical links + sitemap.xml) and optionally
`CONTACT_URL` (corrections link on the Method page):

```
SITE_URL=https://example.com CONTACT_URL=mailto:you@example.com python3 scripts/build.py
```

### Look and the event stream

The site is a dark-by-default monitoring console (light theme via the button, saved in
`localStorage`). The status line, the "Policy event stream" and the per-source check bars
come only from `data/vendors.json`, `data/changelog.json`, `snapshots/index.json` and the git
history of `snapshots/index.json` (see `derive.events()` / `derive.uptime()`). Nothing is
padded: one checker run on record means one cell, with a "history starts" note. Events carry
dates only, never invented times. In CI, check out with `fetch-depth: 0` so the build can read
the index history; with a shallow clone it falls back to the current index (one run).

The compare table takes a query such as `vendor:openai trains:no zdr:available region:none
baa:yes cat:coding` plus free words. Old URL params (`q`, `cat`, `trains`, `zdr`, `region`,
`baa=1`) still work, and `vendor` was added.

Hosting: Cloudflare Pages (build command `python3 scripts/build.py`, output `public`)
or GitHub Pages (publish `public/`).

## Hugging Face export

```
python3 scripts/export_hf.py                      # rewrites hf-dataset/
SITE_URL=https://example.com python3 scripts/export_hf.py   # real site link in the card
```

One row per tool + field: value, status (verified/unverified), detail, source_url,
quote, checked_date. Run it after every change to `data/vendors.json`.

## Policy checker

```
pip install -r requirements.txt
python3 scripts/check_policies.py              # all sources
python3 scripts/check_policies.py --only anthropic.com
python3 scripts/check_policies.py --dry-run    # report only, write nothing
```

If a page returns HTTP 200 but almost no text (an empty JavaScript shell), the checker
loads it again in headless Chromium when Playwright is installed
(`pip install playwright && python -m playwright install --with-deps chromium`; the
nightly workflow does this). Those pages get `"method": "rendered"` in
`snapshots/index.json`. Without Playwright, or with `--no-render`, they are reported as
fetch errors as before.

A diff means "re-read the page", not "the fact changed". Update `data/vendors.json`
and add an entry to `data/changelog.json` only after checking.

Known gaps: openai.com returns 403 to scripted requests; trust.mistral.ai renders
client-side only; AWS pages failed TLS from the build box (they load fine in a
browser). These keep their last snapshot (or none) and are listed in each report.
